# XTicket Codex 执行约束

## 1. 输出与执行方式

- 不要逐条解释即将运行的命令，也不要在每次读取文件后汇报。
- 仅在以下三个节点输出阶段结论：
  1. 审计完成；
  2. 代码修改完成；
  3. 全部验收完成。
- 命令成功且没有影响后续执行时，不需要复述输出。
- 发生失败时，先读取准确错误和相关日志，再修改；不要先进行多种猜测性修复。

## 2. Git

- 默认用户已完成远端同步和分支创建。
- 除非当前任务明确要求，否则不要执行：
  - git pull
  - git fetch
  - git switch
  - git checkout
  - git stash
  - git reset
  - git commit
  - git push
- 开始时只允许执行一次 `git status --short`。
- 结束时执行一次 `git status --short` 和 `git diff --stat`。
- 不要因为 Git 元数据权限问题重复申请和重试。

## 3. Java 与 Docker 构建

业务代码修改完成后，使用以下固定顺序：

```powershell
.\mvnw.cmd -q clean package
docker compose up -d --build backend
```

- 不要依次重复执行 compile、test、package。
- 不要在 package 生成新 jar 之前重建 backend 镜像。
- 只修改测试脚本、文档或报告时，不要重新构建 backend。
- backend 启动检查优先使用健康检查或日志条件轮询，不使用固定的多次 Sleep。

## 4. PowerShell 兼容性

所有 `.ps1` 必须兼容 Windows PowerShell 5.1：

- 文件使用 UTF-8 with BOM。
- 测试脚本内部尽量使用英文输出，中文说明放入独立 Markdown 报告。
- 避免在双引号 here-string 中嵌入 Markdown 反引号。
- 避免嵌套调用 `powershell -Command`；确需调用时使用单引号保护外层命令。
- 不使用 GenericList 作为最终 JSON payload 或报告对象。
- API 请求数组必须显式验证单元素场景，确保：
  - 正确：`"seats":[{"row":1,"col":2}]`
  - 错误：`"seats":{"row":1,"col":2}`
  - 错误：`"seats":[[{"row":1,"col":2}]]`
- 函数返回数组时防止 PowerShell 自动展开。
- MySQL CLI 查询中文字段时显式指定 `utf8mb4`。

## 5. 验收脚本

- 优先使用现有 JUnit、Spring Boot Test、MockMvc 或已有 API 验收脚本。
- 不要为少量业务场景新建数百行 PowerShell 测试框架。
- 新增专项脚本原则上控制在 200 行以内。
- 测试脚本只负责：
  - 准备最少测试数据；
  - 发起请求；
  - 断言结果；
  - 清理或恢复数据；
  - 返回明确退出码。
- 不要在测试脚本中拼接复杂 Markdown 报告。
- 验收记录由 Codex在测试结束后单独更新。

## 6. 分层测试顺序

按照以下顺序执行：

1. 编译或静态检查；
2. PowerShell 5.1 语法解析；
3. 最小请求体序列化检查；
4. 单个快速冒烟场景；
5. 其余快速业务场景；
6. 超时、定时任务等慢场景；
7. 原有回归测试。

- 前一层未通过时不要进入下一层。
- 报告生成或终端输出失败时，不重新执行已经通过的业务场景。
- 仅修改报告文本、输出格式或编码时，只验证受影响部分。
- 超时关单等慢场景只在快速场景全部通过后执行一次。

## 7. 变更边界

- 只修改实现当前验收目标所必需的文件。
- 不进行顺手重构、命名整理、依赖升级或无关格式化。
- 已确认不需要修改的前端、DDL、支付、库存、锁和消息队列逻辑不得扩展修改。
- 达到任务验收条件后立即停止，不追加新的架构改造。
